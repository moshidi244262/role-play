## 1. 产品目标与当前约束

开发一款安装后即可使用的安卓原生角色扮演客户端：保留 SillyTavern 核心角色扮演能力，降低部署、导入和配置门槛。第一版面向个人使用，手机优先，同时适配安卓平板，不开发 Windows 客户端。

- 模型仅通过 API 调用，不集成手机本地模型，不依赖手机运行酒馆服务器。
- 首批服务商：DeepSeek、OpenAI、Anthropic Claude、xAI Grok；支持自定义 API 地址。
- 用户自行导入角色卡、世界书、通用提示词预设和正则规则。
- 本地管理角色、资料、聊天与备份；生成请求会把选中的上下文发往所配置的 API 服务商。
- 先实现可靠的单角色聊天和资料兼容，再加入群聊、语音、图片、插件等扩展。
- 中文界面，常用操作直接可达，高级配置分层展示。
- 通用预设用于叙事风格、角色表现和输出格式；不开发绕过模型安全限制或专门生成露骨色情内容的功能。

“对标酒馆”表示逐步覆盖核心能力，不承诺第一版兼容所有第三方插件、任意脚本和社区资料。兼容范围必须通过明确的支持矩阵与实际测试说明。

## 2. 界面与使用路径

主导航仅保留四个入口：

| 入口 | 首屏内容 | 二级页面 |
| --- | --- | --- |
| 会话 | 最近会话、继续聊天、新建会话 | 会话配置、分支、记忆、提示词检查 |
| 角色 | 角色封面、搜索、标签、导入 | 角色编辑、开场白、世界书与预设绑定 |
| 资料库 | 世界书、预设、正则、玩家身份 | 各类编辑器、导入报告、版本与绑定管理 |
| 设置 | API 连接、外观、数据与备份 | 高级参数、隐私锁、诊断、兼容性报告 |

聊天页默认只展示角色、消息、输入框和发送/停止按钮。重生成、续写、复制、编辑、删除、收藏及分支放进消息菜单；模型和当前配置从顶部进入。重生成保留候选回复，不静默覆盖原文。

第一次使用的路径：添加 API 连接 → 选择模型并测试 → 导入/创建角色 → 开始聊天。后续导入资料自动识别类型，显示包含的对象和兼容情况，再让用户选择绑定对象。类型不明时提供手动选择。

视觉方向：简约、清晰、轻量；以中性色和少量渐变作点缀，支持浅色/深色、字体大小、行距、阅读模式。背景图和磨砂效果可选，优先保证可读性。平板使用列表与详情双栏。提示词技术细节留在高级页面。

## 3. API 连接：四家模板和自定义服务

一个“连接配置”保存的是服务地址和凭证；一个连接可以有多个模型配置。模型切换、采样参数和角色绑定分别管理，避免将 API 密钥与角色卡混在一起。

### 3.1 用户需要填写什么

| 配置 | 普通模式 | 高级模式 |
| --- | --- | --- |
| 服务商 / API 协议 | 选择服务商，自动选协议 | 手动选择 Chat Completions、Responses 或 Anthropic Messages |
| Base URL | 使用服务商默认地址 | 自定义网关、反向代理或其他兼容服务地址 |
| API Key | 用户在安装后的 App 内填写 | 按所选协议配置认证，不把密钥当普通自定义字段 |
| Model ID | 尝试拉取可用模型并选择 | 模型列表不可用时支持手动输入 |
| 生成参数 | 输出长度、创意程度等简单选项 | 支持的采样、推理、停止序列等参数 |
| 额外配置 | 自动使用模板 | 必要时填写项目、工作区、版本头和非敏感自定义头 |

连接模板以官方接口文档为准，以下为本轮研究的设计基线，开发时需要再次核对：

| 服务商 | 默认服务地址 | 拟支持协议 | 适配要点 |
| --- | --- | --- | --- |
| DeepSeek | https://api.deepseek.com | OpenAI 兼容 Chat Completions；其他协议后续评估 | 参数与推理内容按实际模型能力处理 |
| OpenAI | https://api.openai.com/v1 | Responses；另提供 Chat Completions 兼容选项 | 两种协议的请求、流式事件、输出字段分别适配 |
| Anthropic Claude | https://api.anthropic.com | Anthropic Messages | 独立系统指令字段、版本头、认证与流式内容块处理 |
| xAI Grok | https://api.x.ai/v1 | 优先 Responses；旧 Chat Completions 按实际支持情况提供 | 参考官方迁移指引，不假定全部模型支持旧协议 |
| 自定义服务 | 用户输入 | 用户明确选择协议 | 服务商名称与协议分开，不因模型名含 Claude 就改用 Messages |

Base URL 与请求路径分别保存，校验并避免重复拼接 /v1。不能凭网址或模型名字猜测协议。自定义服务并不必然完整实现官方接口，需要连接测试确认。

### 3.2 必须具备的连接能力

- 保存多个连接与多个模型，支持角色默认模型和会话临时覆盖。
- 拉取模型列表失败不阻断手动配置；列表能拉取也不代表生成权限一定有效。
- 提供配置校验、模型列表测试、短文本生成测试；生成测试明确提示会产生少量 API 用量。
- 对密钥无效、模型不存在、权限/余额问题、限流、超时、网络不可达和不支持参数给出中文错误提示。
- 支持流式回复、停止、超时与有限退避重试；请求可能已被服务商处理时不自动盲目重发。
- 根据协议和模型能力显示参数；未确认支持的参数不默认发送。兼容接口也不强制套用某个服务商的全部参数。
- 推理相关返回内容与角色正文分开处理；不把内部或特殊返回字段误显示成角色发言。
- 记录服务商返回的 token 用量；缺少准确计数时标注估算。费用估算使用可更新/手动维护的价格，不伪装成实际账单。
- 不静默更换服务商。切换连接会改变聊天数据接收方，应明确展示目标。
- 第一版使用普通 API 密钥计费方式，不加入网页会员登录、Cookies 导入或会员额度转换。

### 3.3 凭证和隐私

个人自带密钥在 App 内输入，使用 Android Keystore 管理加密密钥并加密保存 API 凭证，不把共享开发者密钥打包进 APK。Keystore 保护加密密钥，不代表 API Key 可以完全避免在运行时进入进程内存。

默认备份不含 API Key，日志与诊断导出脱敏。第三方角色卡、预设和远程图片不能读取凭证或修改目标 API 地址。仓库是公开仓库，提交仅含代码、文档和非敏感测试资料。

## 5. 预设与角色卡冲突的处理设计

### 5.1 不将不同用途的文本全部拼在一起

预设至少区分三类：

1. 生成参数：温度、输出上限等，由能力校验控制。
2. 叙事与行为提示词：视角、文风、节奏、输出格式等。
3. 提示词布局：消息角色、顺序、注入位置及深度等。

角色卡描述身份、性格与背景；世界书补充世界设定；玩家身份说明用户在剧情中的身份；历史与记忆说明已发生的事情。作者注释用于当前剧情方向。

默认配置鼓励预设控制表达方式、角色卡定义角色事实，降低互相覆盖的机会。这是应用的组合策略，不是能强制模型遵守的权限系统，服务商规则与模型能力仍然影响结果。

### 5.2 明确覆盖与兼容模式

- 通用预设默认不自动替换角色卡自带的 system_prompt 与 post_history_instructions。
- 提供明确的采用、合并、忽略选项，并在导入时显示当前策略。
- 角色专用配置可以覆盖全局默认，会话覆盖作用于当前会话；三个层级的差异可检查。
- 新会话保存使用的角色、预设、世界书版本和配置快照，资料更新不无提示改变既有会话。
- 智能默认模式和酒馆兼容布局分开：兼容布局尽量保留来源文件的启停与顺序，转换必须报告，不能用“优化”暗中改写原始文本。
- 导入保留原文和未知字段，自动修改必须可撤回。

### 5.3 冲突提示与检查

能确定的结构冲突直接提示，例如重复同一个提示词块、相同配置字段出现覆盖、未知宏、缺失引用和 token 超额。文本意义上的冲突只做启发式提示，例如同时要求第一人称和第三人称，不能宣称自动识别所有矛盾。

可选 AI 语义检查放在后续阶段，运行前说明资料会发送给选定模型并产生 API 用量。只输出修改建议，不直接改写角色。

提供“本轮 AI 看到了什么”页面：最终请求、提示词块顺序、命中的世界书条目、未命中原因、预算裁剪与正则变换。展示请求不能保证模型一定正确执行，但能解释应用侧是否正确组装。

## 6. 长剧情一致性

- 角色事实、动态状态、摘要与最近消息分别保存，不让自动摘要修改角色卡。
- 固定记忆可以手工编辑；自动抽取记忆标记来源消息，接受、撤销和修订均可追溯。
- 滚动摘要保留关系变化、关键事件、承诺与未完成任务，避免仅压缩成泛泛的故事梗概。
- 可配置避免替玩家决定行动或台词、控制叙述视角与发言长度。
- 超出上下文时预留输出空间、保留核心设定和近期历史，再按规则缩减次要资料；关键内容容不下时提示，不静默删掉身份设定。
- 删除、编辑、换候选或创建分支时，使摘要、动态状态和世界书计时状态跟随正确的历史，不把旧分支事件带入新分支。
- 向量检索作为后续可选补充，不能代替全部明确事实和固定记忆。
- 额外模型检查默认关闭，避免每条回复隐含多次调用；模型表现不能通过 UI 或提示词承诺绝对保证。

## 7. 兼容性要求

格式解析成功、语义已执行、界面可渲染是三个不同指标。导入报告给出：完整支持、部分支持、不支持、保留但未执行，并附具体字段和原因。

- 首批重点：CCv2、常见 SillyTavern 世界书 JSON、Chat Completion 预设、正则 JSON。
- CCv3 作为后续兼容目标，根据规范分别验证 JSON、PNG 数据和资源引用，不将基本字段支持称为全部资源包支持。
- JavaScript 正则与 Kotlin/Java 正则语义并不完全相同。先定义支持子集和对照样例，再评估隔离的 JavaScript 执行环境；不把引擎替换视为天然兼容。
- 常用宏优先，动态变量、复杂表达式和 STscript 后续实现。未知宏在检查页提示，严格模式可以阻止发送；不悄悄删除。
- 社区 HTML/CSS 状态栏先保留原始内容并提供可读的降级展示，后续采用受限渲染；不执行带凭证访问能力的脚本。
- 聊天导入/导出处理发言者、候选、分支与扩展字段，不仅保存可见的文字。
- 用用户愿意提供的有代表性资料建立兼容样例，不访问 Discord 账号或将私人资料上传到公开仓库。

## 8. 安卓技术路线（建议）

只开发安卓，建议 Kotlin + Jetpack Compose 原生界面。

| 部分 | 建议 |
| --- | --- |
| UI | Compose，手机单栏、平板双栏，自适应与无障碍 |
| 持久化 | Room 保存结构化资料与聊天；DataStore 保存偏好 |
| API | 独立的 Chat Completions、Responses、Messages 适配器；网络库在实现时选定 |
| 角色扮演引擎 | 与 UI 解耦：导入、宏、世界书、提示词组装、预算、正则和状态 |
| 文件 | 系统文件选择器；PNG/JSON/备份导入，兼容 Android 分享入口 |
| 凭证 | Keystore 管理加密密钥，凭证默认不导出 |
| 构建交付 | GitHub Actions 编译检查与测试，生成测试 APK；正式版本另行配置签名 |

分层建议：app/ui、core/domain、core/prompt、core/import、data/local、data/network、feature/chat、feature/library、feature/settings。实际模块数量按项目规模调整，不为分层而过度拆分。

锁屏和后台可能影响长连接。默认保证已显示的流式片段及时持久化，异常中断可恢复已保存内容，不承诺系统杀进程后继续生成。若要持续后台生成，再按 Android 当前限制设计用户可见的服务。

第一阶段不需要自建后台或账号系统。以后若分发带共享额度的版本，必须通过服务端保护共享密钥、鉴权与配额，不能把开发者密钥写进 APK。

## 9. 开发阶段与验收

| 阶段 | 交付物 | 验收重点 |
| --- | --- | --- |
| 0：方案 | 本文、功能边界、API 设计、兼容清单 | 用户能理解操作方式、优先级与限制；当前阶段 |
| 1：可用安卓骨架 | 四入口 UI、本地角色与会话、聊天/草稿持久化、备份及记录导入导出、四家 API 适配、测试 APK | 可安装、持久化、切换连接、真实流式对话、停止与错误提示 |
| 2：核心酒馆资料 | CCv2/世界书/预设/基础正则导入与编辑、常用宏、绑定与请求预览 | 资料确实影响请求；未知字段报告；导出后可重新导入 |
| 3：长剧情能力 | 固定记忆、摘要、分支、快照、上下文预算与更多触发规则 | 回滚不串剧情；裁剪可解释；额外调用可控 |
| 4：高级互通与扩展 | CCv3、更多正则/宏、状态栏、群聊、可选语音 | 以资料样例和明确支持矩阵逐项验收 |
| 5：交付收尾 | 兼容测试、备份迁移、稳定签名 APK、说明文档 | 手机/平板实测、升级保数据、恢复成功、凭证不泄漏 |

阶段 1 不靠假回复宣称 API 已验收。协议可先用录制/模拟响应测编码与流式解析；真实调用须使用用户可用的凭证和网络验证，未验证的服务商明确标记。

APK 的本地构建或 Actions 构建能力要先验证。构建通过不等于真机全部功能已验收。测试版签名、正式签名和升级策略在交付前明确，不能因换签名迫使用户卸载丢数据。

## 10. 主要验证场景

1. 导入 CCv2 PNG/JSON，检查角色字段、开场白和内嵌世界书是否完整。
2. 同一关键词命中世界书，取消命中、预算不足、递归上限时给出正确诊断；中文关键词不强制使用英文单词边界。
3. 预设启停、角色覆盖、注入深度与参数限制正确体现在最终请求。
4. 正则区分显示变换与发往模型的变换，保留原始消息，错误规则不挂死聊天。
5. 四家 API 分别验证鉴权、消息角色、流式事件、错误处理和取消；兼容服务另测。
6. 无余额、限流和不支持参数时不无限重试；测试结果与实际返回一致。
7. 网络中断、旋转、切后台或杀进程后，不重复保存消息，保留已收到的片段。
8. 编辑旧消息、切候选和回滚时，记忆与状态同步失效/重算。
9. 备份恢复、数据库升级和文件导出可往返；备份默认不含密钥。
10. 手机/平板的键盘、文件选择、长文本编辑和聊天滚动可用；构建日志不出现密钥。

## 11. 后续需要确认但不阻断方案的事项

- App 的正式名称与图标；暂用 Role Play。
- 第一批真机测试优先使用哪一家 API；四家都保留适配目标。
- 代表性角色卡、世界书、通用预设与正则样例，用于确认社区资料兼容需求。
- 背景图片、主题和气泡样式，在可交互 UI 出来后再挑。
- 是否需要手机和平板之间云端同步：首版用本地备份，不默认建立云同步服务。
- 个人使用还是以后公开分发；影响密钥策略、签名、发布和支持范围。

不需要现在把 API 密钥发到聊天或仓库。实现阶段先完成不含真实凭证的工程和测试路径，再在安全的运行配置中接入凭证。
