# 0.4.1：大预设导入与启动崩溃修复

## 故障与修复

0.4.0 会将 ResourceAsset 的 payload / sourceJson / notes 保存为同一数据库行。用户提供的预设文件约 6.45 MB，含大量扩展原始数据；Android CursorWindow 无法容纳整行，Room 资源订阅抛出异常，导入后和下一次启动都可能闪退。上一轮真实文件验证覆盖了解析和提示组装，没有覆盖这种大小的 Android 持久化链路。

- 大文本分成最多 64 Ki UTF-16 字符的片段，避免切断 emoji 代理对；小文本保持行内。大字段不依赖压缩率或设备的大型 CursorWindow。
- Room 数据库 3→4 迁移只查询 ID 与长度，通过 SQLite substr 在数据库内部无损搬迁，完成前不会读取旧的超大行。迁移包含旧版 1→2→3→4 链路，不清空聊天、角色、绑定、草稿或连接。
- 新写入、替换、读取均为事务；资源观察只用 ID 查询触发完整事务读取。更新大字段会清掉旧片段，删除资源通过外键级联清理。
- 对外 ResourceAsset / 备份格式不变，仍是完整文本；备份和资料导出不会暴露内部片段表。
- 新 ViewModel 不再读取 last_session，冷启动默认进入会话首页；活动重建仍保留同一 ViewModel 中的当前会话。
