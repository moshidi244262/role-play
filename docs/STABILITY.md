# 0.3.2：已有功能检查与优化

本轮从 0.3.1 的交付源码出发，检查聊天、角色与头像、资料导入与绑定、模型连接、草稿、备份、数据库升级和界面操作。范围是修复与优化已实现的功能。

## 检查后已修改的地方

| 项目 | 原来的问题 | 这次处理 |
| --- | --- | --- |
| 长聊天列表 | 渲染每条消息都再次在完整列表中查找位置；新消息还会使不使用深度过滤的旧消息重新执行显示处理 | 改为直接使用列表索引；只有涉及深度的显示正则才按消息深度重新处理 |
| 正则与状态栏 | 显示正则和 HTML 解析分成两轮异步处理，初始空结果可能短暂出现“被显示规则隐藏” | 在同一次后台任务中完成显示替换与结构解析，计算期间保留此前显示结果，不把未完成计算当成规则隐藏 |
| 重复头像 | 同一角色的多个会话重复解码图片；列表重新显示也重新处理 | 使用按位图字节计量的 4 MiB 缓存，短摘要作为缓存键；实际解码仍在后台运行。图库自定义图、角色卡原图与恢复默认逻辑保留 |
| 连续输入草稿 | 每次输入都创建一个等待数据库写入的任务，快速输入可积压旧值 | 使用单一写入任务，等待期间每个会话只保留最新草稿；没有额外的定时延迟。发送和删除会话时清理对应待写入值与缓存 |
| 单会话导出 | 为导出一个会话，先读取所有会话消息再筛选 | 直接查询目标会话的消息。完整备份仍包含所有消息 |
| 开始新一轮 | 重读完整历史仅为获得下一条消息的位置 | 使用数据库最大位置查询，仍在同一事务内保存本轮消息，兼容位置中有空缺的记录 |
| 较大备份与资料 | JSON 编码、备份 ID 重映射、部分资料校验占用界面线程；导出重复生成 UTF-8 字节 | 将相关计算移到后台线程，复用已编码字节。导入和导出异常或取消后复位忙碌状态 |
| 角色保存 | 校验和写入完成前就关闭编辑窗口，失败后输入内容不在窗口中保留 | 保存成功才关闭窗口；无效输入保留，角色配置同时做校验 |
| 数字输入 | 空值、非数字或超出整数范围的输入，可能悄悄保存之前的有效值 | 保留当前输入供修改，并让已有配置校验阻止保存；不会暗中回退旧值 |
| 默认设定合并 | 角色与全局设定各自有效，合并后可能超过绑定上限，却仍创建会话 | 在创建事务中先校验合并结果，失败时不留下无法打开的会话或消息 |
| 模型列表请求 | 取消协程时，同步网络读取可能继续等待；模型列表及单行流式读取缺少读取前的大小限制 | 取消时关闭网络请求；模型列表限制 4 MiB，单行流式事件限制 1 MiB，仍接受末尾没有换行的正常完成事件 |
| 异常流式字段 | 部分格式异常会暴露底层解析错误，`error: null` 也可能被当作生成错误 | 使用固定、脱敏的中文错误；允许空错误字段，不改变真实错误和断流判断 |
| 操作反馈 | 提示显示前立即清空状态，可能取消负责显示提示的任务 | 等提示显示完成再清空，新的提示仍可更新当前反馈 |
| 版本说明 | 设置页写死版本，后续可能与安装包版本不同 | 直接显示构建版本 |

## 检查并保留的行为

- 流式文本仍周期性写入本地；停止、错误与重新打开时保留已保存片段，并标记中断。后台或系统杀进程仍不承诺持续生成。
- 向上阅读长回复会暂停跟随；点击向下箭头恢复。聊天正文继续不显示头像。
- 角色与会话列表使用当前外观，故事设定保留角色快照；恢复头像不改写角色卡原图。
- Token 显示开关只改变界面，服务商返回的用量继续保存。
- 显示正则与状态栏只改变呈现，原始消息仍用于编辑、复制和备份；受限状态栏不执行脚本或请求远程资源。
- 重新生成与编辑仍创建分支，保留原会话。固定记忆仍由用户维护，没有新增自动摘要或隐含 API 调用。
- 密钥仍由 Android Keystore 加密保存；正常应用备份不导出连接密钥。HTTPS、禁止自动重定向和禁止盲目重试的约束保留。
- 单会话导出、完整备份、导入副本及资源 ID 重映射保持原语义；数据库版本仍为 3，本轮不增加迁移。

### 安装

在已经安装的 0.3.1“Role Play 新版”上直接安装本 APK 更新，保留本地角色、会话、头像和连接密钥。0.3.0 与本版使用相同升级签名；原 0.2.0 使用不同包名，仍遵循 [此前的备份迁移步骤](STAGE3.md)。本轮静态核对升级所需的包名、递增版本和签名，并运行数据库迁移/持久化回归；没有在用户设备上执行实际覆盖安装。

## 本轮验证的范围

性能优化依据代码路径中的重复工作、查询范围、线程归属和缓存容量。没有在用户手机上测得前后耗时，因此没有给出提速百分比。设备回归与真实手机、平板体验不是同一项验证。

本轮模型连接使用模拟服务测试取消、断流、分页、异常格式和大响应，没有调用真实生成 API。此前 DeepSeek 的实测结论保留；OpenAI、Claude、Grok 仍不能以模拟测试代替真实账户验收。
