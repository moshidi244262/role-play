# Token 用量、回复长度与上下文裁剪

## 本次问题

旧聊天页的 `用量 7358 / 2048 tokens · 缓存命中 3200` 实际表示服务商返回的 `prompt_tokens=7358`、`completion_tokens=2048`、输入中的缓存命中 `3200`。第二张截图 `6690 / 1564` 同样是输入 / 输出用量，并非进度或已用量 / 最大值，也不是整段聊天累计值。输出计数由服务商定义，部分模型计入思考。

与此同时，已有 API 连接的 `maxOutputTokens` 默认是 2048，真实写入请求的 `max_tokens`（DeepSeek / 兼容 Chat Completions）、`max_completion_tokens`（OpenAI Chat Completions）或 `max_output_tokens`（Responses）。因此第一张截图输出刚好 2048 与触及默认输出上限相符，但旧版本没有保留结束原因，无法仅凭图片证明这条历史回复以 `finish_reason=length` 结束。也无法仅凭其他回复视觉上更长判断它的精确 token 数。

上下文是另一项：默认 48000 **字符**，并且旧代码还隐藏裁剪到最近 200 条有效消息。此前达到字符预算会裁剪发送给模型的历史；本地聊天不删除。输出上限不能扩大上下文容量。

## 修改后的行为

- 聊天用量改为 `输入 X · 输出 Y tokens · 缓存命中 Z`，只显示服务商实际返回的计数。
- API 连接的“单次回复长度”移到可见设置，可输入明确上限或选择常用数值。指定数值不再被 App 另行收缩；数值必须在实际模型支持范围内，服务商仍可提前结束或拒绝不支持的参数。
- Chat Completions / Responses 可选“使用服务商默认输出上限”，以存储值 0 表示省略可选输出参数，**不会向 API 发送 max_tokens=0**。这表示跟随默认值，不是无限输出。Claude Messages 要求明确正值；不能把 0 当无限。
- 会话设定 → 上下文与扫描选项可选择“不限制 App 上下文”，存储值 0 保留全部有效聊天，不裁剪固定资料，也不再隐藏限制最近 200 条。有限预算可设 2000～2000000 字符；达到预算时按整条旧消息裁剪并提示数量。
- 取消 App 裁剪不会扩大模型容量，也不会取消世界书独立预算。服务商可能因上下文过长拒绝请求。设置里的默认资料只影响新会话；已有会话需要单独修改。
- 上下文预览分别显示有效字符预算、API 输出限额模式和世界书预算；明确区分设置与实际用量。
- 解析三种协议的长度停止事件。回复触及输出或模型上下文限额时保留正文、实际用量和 `length_limited` 状态，在消息下显示可调整上限或续写的提示；关闭 token 显示不会隐藏这个提示。Responses 的 `response.incomplete` 保留最终 usage，而非只转成通用异常。传输断开继续使用原来的 `interrupted` 状态。
- 设置及结束状态随备份保存恢复；数据库结构不变，现有连接的 2048、会话的 48000 保持原值，不静默改动用户设置。

## 现有已安装版本可立即调整

设置 → 编辑当前 DeepSeek API 连接 → 高级选项 → 最大输出 token 数。现有版本可改为 8192 / 16384 等模型支持的额度，下一次请求生效。上下文字符预算在当前会话的设定 → 上下文与扫描选项中修改；它与最大输出是两项不同设置。

官方参数来源：

- [DeepSeek Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)：最大输出、默认额度、上下文容量和 `finish_reason`。
- [Claude Messages](https://platform.claude.com/docs/en/api/messages/create)：必填输出额度、服务商停止原因及思考计数。
