# 长剧情记忆与后续插件的衔接（未发布）

用户已确认当前 UI，要求本轮适当优化长剧情，并为后续记忆插件保留切换空间。当前 App 没有酒馆 JavaScript 插件运行环境；本轮不把内置记忆当作插件兼容层。

## 本轮行为

- 在“剧情记忆”和会话/新会话默认设定中提供“启用内置剧情记忆”总开关。旧配置缺少此字段时保持原有行为；自动整理及摘要替代仍各自默认关闭。
- 关闭总开关后，不发送内置固定记忆和生成摘要，不进行内置自动整理或手动摘要请求，也不以摘要替代历史。用户保存的自动整理、压缩偏好保留，重新启用后生效。
- 聊天原文、固定记忆、摘要及来源指纹均保留；分支和备份恢复保留总开关。普通上下文预算仍独立生效，关闭内置记忆不等于取消预算裁剪。
- 恢复启用需要先保存。暂停/恢复本身允许保留来源已过期但未修改的旧摘要；来源检查仍会阻止发送该摘要，用户可随后重新生成。修改过的过期摘要不能在启用状态下保存为有效摘要。
- 内置固定记忆和摘要按事实文本发送，保留其中的 `{{...}}` 原文，不在 App 内执行记忆中的变量宏。导入的角色卡、预设、世界书及正则继续走各自原有流程，内置记忆不写入它们的源 JSON 或变量。
- 上下文预览明确显示内置记忆启用/暂停状态，并继续区分摘要替代与普通预算裁剪。

## 与附带资料的关系

本地检查发现，一份预设引用独立的角色记忆链和剧情大总结变量；另一个名为“提取角色最后总结”的 JSON 实际是正则规则，引用酒馆变量和数据库操作。它们不是本轮可以直接运行的通用插件包。

本轮不复制、上传或改写附带资料的正文，不把它们的变量映射到内置摘要。今后接入具体记忆插件时，可先关闭内置记忆，再为该插件适配读取历史、保存状态和构建上下文的接口，避免两套摘要重复注入。本轮仅建立可切换边界，不承诺兼容尚未指定的插件。

参考：[酒馆 Summarize 文档](https://docs.sillytavern.app/extensions/summarize/)；[酒馆扩展接口文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)。

## 验证

- 新增单元测试覆盖暂停/恢复对实际发送内容的影响、保留预设/世界书与完整历史、记忆文本不执行变量宏、关闭后不建立摘要生成计划，以及旧配置和备份行为。
- 新增安卓测试覆盖暂停时保留过期摘要与原偏好、恢复后必须先保存，以及真实 Room 分支/备份恢复后的开关与上下文。
- 仓库 CI 编译、单元测试、Lint 和 Android API 29 测试结果待补充；本轮未使用真实密钥调用模型，未发布新 APK。
